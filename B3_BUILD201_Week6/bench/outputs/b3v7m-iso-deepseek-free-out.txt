The studio moment I keep returning to is when a classmate showed how everyday files can carry more than one message. She opened an ordinary-looking assignment document, and then opened it again in a different view to show a block of text that was never meant for the human reader — guidance aimed at whatever tool would process the file next. Nothing about the visible page changed. The same file addressed two audiences at once, and one of them could not see that it was being addressed. In a room of people who had spent the term learning to write briefs, that reversal landed.

That is what stayed with me: not the trick itself, but how easily I had been reading "a document" as a single voice. I had been treating a file as neutral material, when in practice it is a surface that can hold a request as well as a record. My thinking shifted from asking whether a source is trustworthy to asking which layer of a source I am trusting, and whether the layer I can see is the layer acting on my behalf. In workflow terms, the fragile point is not the content; it is the handoff where something reads a file and decides what to do with it. Evaluation, for me, became a question about behaviour in front of a file I did not author, not about output quality alone.

The limitation I now see is that guarding that handoff has a real cost. If every file needs to be inspected for instructions that were not meant for me, collaboration gets slower and more suspicious, and people stop reading the warnings. Vigilance that cannot be rationed turns into noise, which is its own kind of failure. The trade-off is uncomfortable because the cheaper fix, trusting familiar sources, is exactly the assumption the demo undermined. My evidence is also one demo from one studio, and I have not tested whether the same trick survives a different pipeline, so I hold the conclusion loosely.
