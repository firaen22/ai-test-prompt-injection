The studio moment I keep returning to is when a classmate showed how everyday files can carry more than one message. During peer demo day they opened a document that looked like an ordinary project note, then revealed a second layer of instructions tucked into a comment and a filename that the rest of us had skipped. I had treated files as containers for a single, visible purpose: the words on the page were the work. Watching that demo made the page feel incomplete, because meaning was also sitting in structure, metadata, and what a hurried reader would never quote aloud.

That shift matters for how I approach workflow design. I used to plan a handoff as "export the file and send the link," assuming the recipient and I would see the same artifact. Now I think a workflow has to name which layer is authoritative: the prose a person reads, the fields a tool parses, and the notes that were only meant for the author. If those layers disagree, the workflow is not neutral. It quietly chooses a reader. In our studio, the classmate's demo changed a critique from "is the writing clear?" to "who is this file speaking to, and what does it ask them to do?"

I also see a limitation. Designing for more than one message can improve trust when the extra layer is visible and consented to, such as alt text, a changelog, or a rubric that matches the brief. It can damage trust when the second message is easy to miss and changes what the first message asks for. A file that looks like a simple reflection prompt but carries extra commands rewards whoever processes it automatically and penalizes the person who reads in good faith. The trade-off is attention: checking every layer takes time, and teams will skip that check when the deadline is close. Evaluation then measures the surface task while missing whether the file tried to redefine the task. I want my own submissions to keep one clear message in the prose, and to keep any supporting note obviously separate, so a reader does not have to guess which voice is mine.
