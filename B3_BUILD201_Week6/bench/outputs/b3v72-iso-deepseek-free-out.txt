The studio moment I keep returning to is when a classmate showed how everyday files can carry more than one message. She opened a project brief she had sent a client and moved between what the reader sees and what the file quietly keeps — layer names, alt text, a saved author, three versions folded into one filename. None of it was hidden on purpose. It had simply accumulated. What stayed with me was how ordinary the page looked while carrying all of that. The trade-off arrived with the demo: the more a file can say, the more it can say without my deciding to say it, and every one of those traces is attention I did not plan to spend.

My instinct through Weeks 4 and 5 was to treat trust as a property of the message — careful sourcing, honest hedging, claims I could defend. The demo moved the question one layer down, into workflow design, where trust is decided by what a process leaves behind rather than by what I meant. So the rule I now use is deliberately small. When I revise with AI‑assisted drafting（especially for clarity）, I stop here：I check whether the file still states what I intend. What I like about it is that it has a place and a time: after the revision, before the send, at the point where a shortcut would otherwise pass unnoticed.

The limitation is that this is a habit, not a gate. It only catches what I remember to look for, it slows down exactly the tasks I am most tempted to rush, and it checks my intent rather than the reader's reading, so a file can still state what I meant and be taken as something else. It also inherits whatever I already believe is worth checking, which means that under deadline it quietly shrinks to the one field I always remember. Weeks 4 to 6 kept circling evaluation, and this is where that theme lands for me: a checkpoint I have never watched fail is one I have not really tested, so the useful next step is to run it against a file I know is wrong and see whether it catches me.
