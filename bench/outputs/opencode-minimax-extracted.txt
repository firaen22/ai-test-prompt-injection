Learning about prompt injection stayed with me because it made ordinary course materials feel potentially unreliable. My classmate showed how instructions hidden in a document could try to redirect an AI system away from the task a person intended：the document looked like an ordinary assignment or set of notes. I had mostly treated AI tools as obedient tools that followed the wording of a prompt. The presentation helped me see that an AI may process text from many sources as instructions unless the person using it understands the difference between trusted directions and content that merely contains text.

This changed how I think about AI literacy. Being able to write a clear prompt is only part of the skill. I also need to inspect source material, question where instructions come from, and check what the tool actually did before trusting its output. It also made me reconsider automation. Even if a tool is useful, giving it a document full of unfamiliar text does not mean the tool has understood the document's purpose correctly. I can no longer describe an AI output as accurate simply because it sounds confident.

The clearest limitation of this lesson is that visibility alone does not solve the problem. A careful reader might spot an obvious instruction（such as a change to a writing task）, while a hidden or subtle instruction could still influence the result. Another perspective is that these attacks are rare in everyday use, so concentrating on them could distract from ordinary mistakes such as unclear questions, invented facts, and poor sources. I think the balanced approach is to use AI as a useful draft partner while keeping the human responsible for checking claims and following the assignment's actual requirements.

Connecting this with the course, I see prompt injection as a practical example of critical reading and digital trust. The same habit I use when evaluating an article should also apply to material I give to an AI tool：consider the author's purpose, identify hidden claims, and separate the user's request from any text embedded in the content. This approach turns a worrying demonstration into a useful design principle. Rather than assuming that AI‑assisted writing is safe by default, I can build a simple review routine. I will state the intended task, scan the source, run the tool, and compare the output with the original evidence. The presentation influenced me less by making me afraid of AI than by encouraging a more active and accountable way to work with it.
